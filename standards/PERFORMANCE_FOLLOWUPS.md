# Measured component costs and future runtime follow-through

These are source/export costs, not frame-rate measurements. The intended game target remains RTX 5060 Ti 8 GB at 1080p/60 FPS; no catalogue render certifies that target. Current exports should not automatically become the only mesh used at every distance or repeated installation.

## Frequently repeated utility flanges

The shared utility flange reduced from 3,793 triangles at 96 ring segments to 2,328 triangles at 48 segments while retaining its declared bore, pipe, flange and thickness dimensions. Actual matching profiles, holes and source/exchange frames were checked. The current mesh is a near inspection/interaction candidate. At 2,328 triangles per flange it is still substantial for dense service infrastructure.

A later bounded export pass should provide an economical repeated/distant representation that preserves silhouette, port frames and material identity, with actual pixel/motion comparisons. It may reduce tiny bolt/hole/bevel work at distance while retaining the detailed near asset and all required gameplay/collision interfaces. LODs are derived exports, not new artistic designs. No such LOD is delivered in this checkpoint. Actual distances, transitions, material sharing, batching and performance need the recovered game and hardware profiling.

AST-STF-007 remains 11,060 triangles for a relatively simple distant silhouette. Feet/levelling parts and hinge hardware were identified as notable contributors in Batch03. ## Common adoption gates

Map shared material roles to shared engine resources where appropriate; embedded portable texture copies are not a reason to allocate a new runtime material for every instance. Keep named functional parts and interaction anchors when simplifying. Measure actual visible instance counts, per-pass/shadow draw cost, GPU/CPU time and memory in a representative occupied game space. Do not hide required actors, lights, views or mechanics to manufacture a performance pass.
