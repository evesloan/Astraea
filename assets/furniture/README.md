# Astraea Day furniture family

New independent Blender component production, 2 October 2026. These are three newly authored catalogue assets, not recovered files or a reconstruction of the lost game. No live project is included or altered.

| ID | Asset | Nominal dimensions, X / Y / Z | Evaluated triangles |
|---|---|---|---:|
| AST-FUR-001 | Two-person day window bench | 2.400 / 0.929 / 0.997 m | 4,936 |
| AST-FUR-002 | Companion reading chair | 0.940 / 0.929 / 0.997 m | 3,872 |
| AST-FUR-003 | Small day table | 0.980 / 0.620 / 0.665 m | 1,848 |

Both seats have a measured 0.475 m unloaded cushion crown. The table is a forward-of-knees surface for drinks and a book, not a claimed tucked-in dining/work table. No broad-body or species fit has been established.

## Design and editable source

The seating uses swept walnut side cheeks, recessed ivory inner liners, narrow upholstered arm pads, two-stage load-bearing sled supports and a fitted rear shell. Upholstery is genuinely crowned and tapered by varying cross-section rings, with separate low-poly welt geometry. The companion chair uses the same construction in teal. The oval stone-top table has waisted timber trestles, a joined stretcher and a small book shelf. Metal is limited to join pins and a recessed table edge inlay.

Each `.blend` keeps named semantic mesh objects, useful editable bevel modifiers, optional disabled upholstery subdivision, original packed 256px textures, and a floor-origin parent. Every asset uses metres, +X across width, +Z up and front -Y. The source generator `build_furniture.py` preserves all shape parameters and construction paths. Production was script-assisted intentional design, not literal manual GUI modelling. References guided palette, material restraint and day-use character; no reference pixels or copyrighted decorative artwork were copied.

Run `/usr/bin/blender -b -t 4 --python build_furniture.py` from any directory. It requires the shared `../../standards/materials.py` and `../../materials/` alongside this folder. The shared material function supplies separate ordinary Principled material roles. Main UVs use real part coordinates divided by the role's metre tile scale; wood grain follows the part's principal length axis. Welt UVs use measured tube circumference and path length.

## Export and proposed interaction

The GLBs contain a single evaluated static visual mesh with separate role primitives: six for either seat and four for the table. Consolidation happens only after the editable `.blend` is saved. Exported scene graphs contain two nodes (floor-origin parent and visual mesh), use standard glTF Y-up conversion, embedded base-color textures and applied scale. Semantic part descriptions stay in the source and manifest. No collision, controller or automatic interactions are exported.

Each manifest gives source hashes, measured bounds, material/triangle counts, construction relationships, contact and approach proposals. Separate `.collision_proposal.json` files contain conservative per-part box proposals. These deliberately retain separate seat, side and support parts instead of filling the entire approach area with a whole-chair hull. They require engine and actor review before use.

## Component evidence and limits

`qa/render_qa.py` independently reopens each `.blend`, verifies finite evaluated geometry and exact floor contact, then creates a neutral three-quarter 640×360 view, 1280×720 detail, and 640×360 standing-eye and seated-eye views with an independent 1.75 m scale proxy. The studio, camera, proxy and lights are QA-only and never saved into the asset sources or GLBs. `qa/label_qa.py` labels every image as Blender asset QA. The proxy is a scale aid, not a game actor rig.

`qa/validate_glb.py` parses the binary glTF without Blender and checks embedded texture/material references, UVs, finite attributes, dimensions, applied scale, triangle counts and face/vertex-normal agreement. Results are in `qa/glb_independent_validation.json`; each reload audit is separate. All current meshes have zero degenerate triangles and zero opposed triangle normals.

The final neutral 640px views for all three assets and the bench 1280px detail use materials-02. Earlier chair/table detail and body-scale evidence is preserved under `qa/pre_material_02/` and labelled as an earlier material phase. Its geometry is unchanged, but it is not final texture/export proof. The bench eye-height views were also refreshed. `qa/RENDER_MANIFEST.json` distinguishes every image's scope.

Independent export review found a UV-layer-name mismatch during consolidation, which was repaired by normalizing each evaluated mesh's single active UV layer before joining. All final primitives now have one TEXCOORD_0 set and zero collapsed UV surface area; tiny seam caps retain planar metric UVs. `qa/uv_repair_independent_report.json` was generated by the separate reviewer's parser against the final GLB bytes.

This is Blender component evidence only. It establishes no Godot integration, room fit, controller contact, collision behavior, animation quality, CRT treatment, live draw-call budget or target-PC performance. Final visual review and parent-controlled frozen backup are required before the catalogue expands.
