# Source-only matched-content measurement driver r002

Separate successor to c9a21f08's paused driver. The default-off D04 candidate, production source, repaired Windows deliverable, residency systems and original driver are unchanged. Candidate prerequisites match CANDIDATE_PINS.json; a567132b and prior independent retention receipts were checked before editing. No new construction, export, import, full ship run or laptop launch occurred.

## Changes

- Fixed tuple-key bugs in timeout validation and process deadline calculation. Python prerequisite checks execute even with python -O.
- Dry plan is the default and creates no result directory/process. Execute remains a separately authorized laptop action, uses four sequential fresh processes, and stops after a failed/error-logging mode.
- Pins the repaired SOURCE_CONTRACTS manifest and unchanged candidate bytes before execution. All four runs must use the same isolated source copy and official editor binary. It does not install the candidate or alter project.godot.
- Captures exact loaded room IDs, load/release counters, activation count, active optimized IDs and irreversible fallback state. The summary requires actual sampled batching activity and positive saved submissions; final controller counts alone no longer establish that batching was exercised.
- Matches complete current scene light state (including non-budget lights, transforms, colors, ranges, layers, energy and visibility), selected lights, actor/camera, effects, resolution, frame cap, vsync, engine and source identity. Missing modes, differing/unstable content or incorrect occlusion toggles prevent a pure-render comparison claim.
- Records per-frame controller cumulative time and sampler cost, activation build_us and fallback events. Summary reports controller/sampler p95 overhead. Existing light-guard max_us remains a high-water measurement, not a timing distribution. Recording all lights adds overhead to every mode; reported frame intervals include that overhead.
